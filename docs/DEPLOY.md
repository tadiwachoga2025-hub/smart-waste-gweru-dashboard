## How production deploys

- Static Vite React PWA. Remote build on Vercel: `npm run build` → `dist/` (see `vercel.json`).
- `vercel.json` pins framework/build/output and sets `Cache-Control: public, max-age=0, must-revalidate`
  on `sw.js`, `workbox-*.js`, `manifest.webmanifest` so PWA updates propagate.
- SPA client-side routing: none (no react-router), so no rewrite rules are needed.
- `engine.py` / `notifier.py` / service-account JSON / `.env*` / `.venv` are excluded from CLI
  uploads via `.vercelignore` and never run on Vercel — the Python engine runs on its own host.
- Deploy command (from this dir, logged in as `tafadzwa2000`): `vercel --prod --yes`.
  Tree may be dirty; CLI uploads working-tree files. No git remote/push is required for a CLI deploy,
  but committing is still recommended for history (see below).

## Environment variables (Vercel project)

Only one `VITE_*` var is read by the frontend (`src/lib/tiles.js` → `VITE_CARTO_KEY`;
`src/firebase.js` uses a hardcoded public web config, no env needed):

| Var | Production | Preview | Notes |
|---|---|---|---|
| `VITE_CARTO_KEY` | set | set | CARTO Voyager basemap key; without it the map falls back to OSM tiles |

`.env.example` documents `VITE_CARTO_KEY` (empty placeholder — fill locally, never commit `.env*`).

## Realtime Database rules (published manually, not by the Vercel deploy)

`database.rules.json` (generated by `node scripts/build-rules.mjs` — keep the two in sync)
is **not** pushed by the Vercel deploy. It was published to the live database on
2026-10-19 straight from this repo's generated file, replacing a temporary open test
ruleset (anonymous read/write, expiring 2026-11-05). The published rules have no expiry.
Re-publishing is still manual:

1. Open https://console.firebase.google.com/project/smart-waste-gweru/database/smart-waste-gweru-default-rtdb/rules
2. Paste the full contents of `database.rules.json`.
3. Click **Publish**. Verify the engine trail reads as admin/officer and stays denied otherwise.
4. Alternative (non-interactive, not yet wired): `npm i -g firebase-tools`, `firebase login`,
   add `firebase.json` + `.firebaserc`, then `firebase deploy --only database --project smart-waste-gweru`.
   A REST path also exists (service-account OAuth → `PUT .../.settings/rules.json`) but no
   script for it is checked in — do not improvise one against prod.

## Engine (runs outside Vercel)

The prediction/routing engine is a single-writer Python process and is **not**
deployed by Vercel. It runs continuously from `.github/workflows/engine.yml`
(5-hour jobs handed off by a 5-minute schedule) with the service account stored
as the encrypted `FIREBASE_SERVICE_ACCOUNT` Actions secret. Docker, Render and
systemd alternatives, health checks and operations are documented in
`DEPLOYMENT.md`.
